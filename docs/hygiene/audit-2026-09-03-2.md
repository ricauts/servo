## Method note

Neither scanner found any of the 23, which is the same conclusion `hyg-audit-06`
and `07` reached and question 78 predicted. A guard that fails open, a comment
that says the opposite of its code, a documented procedure that cannot execute,
and a sizing premise contradicted by the file it governs are all invisible to a
reference graph and to a phrase linter. 38 agents, 994 tool calls; every
reported finding was reproduced first-hand by an agent that had not written it,
and the four load-bearing guard defects (109, 111a, 112a-c, 113) were
additionally reproduced by hand outside any agent before this report was
written — `checkStagedDiff("")` returning `ok`, a 2 MB child-process read
throwing `ENOBUFS` under Node's default, `TIER_C_FILES` listing neither docling
overlay, and the merged docling config rendering no `internal` network.

The verifier also removed a piece of evidence rather than a finding.
Question 109's "three of the last 400 commits already exceed 1 MiB" was a
**shallow-clone artifact**: all three SHAs are in `.git/shallow`, so git renders
each grafted boundary commit as a root adding the whole tree, and one of them is
a spec.md-only `docs(spec)` commit that cannot be 3.4 MB. Measured with the
grafts excluded, no reachable commit crosses the threshold — the largest is
740 637 bytes, 71% of it. The code defect 109 reports is unaffected and
reproduces exactly; only its "this already happens here" evidence was wrong, and
the question now records the trap so the next tick does not re-derive it.
