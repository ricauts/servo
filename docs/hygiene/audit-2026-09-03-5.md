## What the lenses found

Eight lenses ran, each over a surface neither scanner reads, each blind to the
others: the Prisma schema versus its callers; `package.json` scripts and every
executable entry point; `.github/workflows/` and what CI actually proves; design-
system token integrity beyond raw hex; unreachable or fail-open logic in the
security-critical files; the HTTP route surface compared against itself;
`docs/design/*.md` versus `spec.md` and the code; and environment variables end
to end.

Twenty-four candidates were produced. Each went to two skeptics with distinct
lenses — one re-checking coordinates byte for byte, one hunting for what would
make the finding already-known or immaterial — neither having seen the finder's
reasoning, both told to default to refuted. **Forty-seven verdicts were cast;
eighteen candidates were killed and six survived unanimously.** One candidate
(`npm run test:docling`'s compose project name) received a single verdict because
a skeptic hung on a shell call this runner could not answer; that verdict was a
kill, so the missing second changes nothing. Everything killed stayed killed —
no finding was rescued by the author.

Among the notable kills: the `datasource_readable_by_*` empty-fixture views (a
real fact, but already recorded in `spec.md` and defused by the connection layer);
three `docs/design/` contradictions that turned out to be superseded rather than
disagreeing; and the unpinned `adobe/s3mock:latest` tag, killed twice as
immaterial because CI's other pins bound the run.

The six survivors are recorded as **questions 131 to 136** in §14 of `spec.md`,
each with its coordinates. In summary, worst first:

1. **Question 131 — SECURITY, the approval gate.** `resumeAfterApproval`
   (`src/lib/ai/engine.ts:700-718`) is the only tool-execution site in the engine
   that checks tool-registry presence but never `ctx.policies`. Its twin in the
   loop (`:544-547`) refuses on `!tool || !policy`. An admin who disables a
   HIGH-risk tool while its approval is pending has not stopped it.
2. **Question 132 — SECURITY, privilege escalation in the KB.**
   `POST /api/kb/collections/[id]/grants` applies only a role gate and an
   existence check; there is no `canAdministerCollection` in the tree at all,
   while the document sibling applies `canAdministerDocument` in both halves.
   `kb.share` is granted to `AGENT`. Separately, `revokeGrant` is an unscoped
   `deleteMany({where:{id}})`, and *neither* grants route checks that the
   `grantId` belongs to the object in the path.
3. **Question 133 — audit integrity.** `purgeGone`'s citation guard reads a
   `Json` column through `JSON.parse(String(...))`, which throws on every array
   Prisma returns, so the refusal branch is unreachable and cited documents are
   purged. The test that pins the refusal passes only because it writes a shape
   production never writes.
4. **Question 134 — SECURITY, a false control in the docs.**
   `docs/knowledge-base.md:60-61` says the embeddings endpoint follows the egress
   allowlist. `src/lib/kb/embed.ts` calls bare global `fetch` and never imports
   `@/lib/egress`; two source comments name `kb.embed.baseUrl` as the canonical
   *exemption*.
5. **Question 135 — the design system's own contract.**
   `servo_design_system/tokens/base.css` is imported at `src/app/globals.css:23`
   with no `layer()`, so its bare `h1..h6` and `a` rules outrank every Tailwind
   utility, which all live in layers.
6. **Question 136 — an operator procedure that cannot run.**
   `scripts/dev/responsive-audit.mjs:8` hardcodes a Windows Chrome path with no
   fallback, and `README.md:101` tells every operator to run it.

Every one of the six was re-verified by hand against the bytes before this report
was written — the three SECURITY ones by reading the full route and engine
bodies, the `purgeGone` one both that way and by executing its exact expression
(`JSON.parse(String([{docId:"x"}]))` throws `"[object Object]" is not valid
JSON`), the cascade one by confirming `base.css` contains no `@layer` at all, and
the responsive-audit one by reading all six puppeteer entry points.
